# 石英与 Super-Agent 分工

参考用户提供的文章《通了个宵，终于把 Super-Agent 架构玩明白了。》：
https://linux.do/t/topic/3109398

文章讨论 Router/Worker 分工、事件触发、异步交互、计算与状态及执行环境分离，以及独立 Watchdog。适合石英的部分是让协调会话不等待长任务结束、按任务关联后续事件，并让执行状态独立于一次模型响应持久保存。

在本项目中，石英承担协调角色，原生开发子代理和本机 Codex、Claude、DSH 承担执行角色。设备插件与 C# 被控端负责连接、命令和事实记录，不配置第二个协调模型。本机仓库、工具链和登录状态留在本机，远端保存设备与任务关联。

已有任务事件优先关联原设备和会话，新任务才需要石英判断交给谁。前台只接收受理结果与任务标识，后续通过事件与持久监工回传。历史记录可以按需读取，避免每次向主聊天灌入全部日志。

后续如果需要跨项目主动巡检，应单独定义触发来源、授权范围、预算和停止条件。Watchdog 先检查事实，例如心跳、最后进展和等待确认；语义判断只用于解释异常或提出修复。不能因为“很久没输出”自动重复输入，更不能把用户未授权的操作当作恢复措施。

这篇文章是架构参考，不是本项目已完成能力的证明。桌面接管、断线恢复和消息送达仍分别按真实运行结果验收。
